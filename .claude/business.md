## Use-cases (Platform skeleton — Phase 1)

### Platform (skeleton)

- **User login** — POST `/login` with email + password + remember flag; validates via Auth::attempt; on success sets session + redirects /dashboard; on fail returns validation error `invalid_credentials`. Session manages is_active flag (future port guard), user locale preference. Throttled: 10/min per IP and 5/min per email+IP; a throttled attempt shows `auth_throttled` (wait time) under the email field and is logged as `login_lockout` (no causer, DB only). Logged to Activitylog (login/login_failed/logout events).
- **Forgot password** — GET /forgot-password shows form; POST sends reset link via Mail::queue; link valid 60 min (config/auth.php); user follows to GET /reset-password/{token} + email prepopulated; POST /reset-password updates password via Password::reset. Forgot (5/min per IP) and reset (5/min per IP) are rate-limited. A link request for an existing email is logged as `password_reset_link_sent`; the response is identical for known and unknown emails. A successful reset logs `password_reset` and logs out every phone.
- **User profile + password change** — GET /profile (no page props, reads shared auth.user) · PUT /profile updates name/email/locale (ProfileService, updates session('locale') + app()->setLocale()) · PUT /profile/password validates current_password via Hash::check, updates password through `ProfileService::changePassword`, which logs out the other mobile phones (see "Use the mobile app").
- **Manage users (CRUD)** — Authorized by policy (viewAny/view/create/update/delete users). QueryBuilder with AllowedFilter search/role/is_active/created_at. Pages Users/{Index,Form}. Create/Edit via useForm (Precognition). Deactivate via is_active toggle (soft revocation, reactivatable). Delete removes user (hard delete, no soft-delete on User model).
- **Manage roles + permissions** — Authorized by policy (viewAny/view/create/update/delete roles; delete blocks SYSTEM_ROLES=['admin']). Pages Roles/{Index,Form}. Form: PermissionManager component to toggle flat permission strings. RoleService::getPermissionsGrouped() groups permissions by resource (2nd word) for UI affordance. No edit of permission catalogue (that is admin-only via PermissionSeeder).
- **View audit log** — Read-only, permission-gated (view audit logs). Pages AuditLogs/{Index,Show}. Lists with filters (subject_type, created_at, causer search). Show renders a before/after table per changed field; raw JSON sits in a collapsed section. Activity writers: User/Role LogsActivity, LogAuthenticationActivity (login/logout/login_failed/login_lockout/password_reset/password_reset_link_sent/password_changed; login_failed and login_lockout have no causer and do not appear in this viewer).
- **Revert from the audit log (2026-11-03)** — A user with `revert audit logs` (Admin by default) and the right to edit or delete the record can undo a change from the audit log: a plain field update, a create, a delete (undone by restore) or a restore (undone by delete). One user action is one batch: every row of that action (e.g. a client with its contacts and objects) reverts together, all-or-nothing. A revert is blocked with a shown reason: the record changed since the logged value (conflict, marked per field), later activity on the record, a non-draft document, a batch member that cannot be reverted, an entry already reverted, a primary contact reverted alone, lifecycle fields (status, number, stamps, money, assignment), login / AI / download / access events, identity and permissions, Invoice / Quote / Contract updates, unsupported models. Reverts are logged like any change and can themselves be reverted (redo). Rows written before batching revert one by one. The list shows the status per row; Show shows the before/after table with conflicting fields.
- **View media library** — Read-only, permission-gated (view media). Pages Media/{Index,Show}. Displays uploaded files via MediaLibrary. Show page has image preview. No delete yet (future). Mirrors TemporaryUpload lifecycle. Does not list quote, employee or signed-contract files, nor task attachments (those are reached only through their own page).
- **Upload temporary files** — POST /uploads (multipart file) stores in TemporaryUpload (uuid PK, user_id FK, session_id, MediaLibrary collection). Returns 201 {uuid,name,file_name,mime_type,size,url}. DELETE /uploads/{uuid} removes. Consumer forms use uuid validated by OwnedTemporaryMedia rule → service moveToModel($owner, 'collection', $uuid). Cron daily purges TemporaryUpload rows older than 24h.
- **Switch language** — GET /language/{locale} (unauthenticated, full-page reload, no DTO) sets cookie + session locale; redirects back; LocaleMiddleware resolves order: user.locale → session → cookie → Accept-Language → sk. Supports sk/en today (uk will be added on port). App.Enums.SupportedLanguage #[TypeScript].
- **View API documentation** — GET /docs (auth + permission:view api docs) shows Scribe v5 docs. Only api/* endpoints documented. Strategies: GetBodyParamsFromSpatieData, GetResponseFromSpatieData. Covers auth/login, profile endpoints.
- **Navigate app** — Inertia shared nav from NavigationRegistry (BE-driven via #[NavItem] attribute discovery). NavItems on controllers: Dashboard, Users, Roles, AuditLogs, Media, Profile→settings. Icon via NavIconEnum (BE-declared, Material Symbols); invokable controllers (Dashboard/Prehľad) are discovered too. Gated by permission + policy (e.g. Users nav visible only if user can view users). Nav links full-page load (no SPA routing; each click → server round-trip). On port: extend ICONS map for new domains (BuildingOffice2Icon for clients, etc.).
- **View dashboard** — GET / renders Pages/Dashboard.vue (placeholder welcome card, no props; reads shared auth.user.name). On port: add widgets (recent quotes/invoices, upcoming jobs, notifications, team activity).

## Use-cases (Phase 2 — Tenancy, IMPLEMENTED)

- **Bootstrap first account (app:create-owner)** — DevOps invokes `php artisan app:create-owner` (interactive prompts or flags: name, email, password, company_name, ico + 11 optional supplier fields --address-line, --city, --postal-code, --country, --dic, --vat-number, --vat-payer, --contact-email, --contact-phone, --iban, --swift; validates via TenantSupplierProfileData before any DB write) → creates User (owner) → Tenant (firma, populated with supplier data if provided) → TenantInterface (colour nullable) → TenantMembership (owner active) → RoleTemplatesSeeder::seedForTenant seeded 6 role bundles → Admin role assigned. User can log in and add more tenants/members. If supplier fields not provided, owner must complete profile in Settings→Invoicing before any invoice can be issued (though drafts allowed).
- **Import legacy data (one-off, 2026-11-05)** — An operator runs the encrypted import seeder (`db:seed --class=LegacyImportSeeder`) once locally and once on production (Cloud Command), after the owner account exists; re-runnable. It imports the owner's 5 active legacy firms (official register data wins for name, IČO and address), their clients (property managers; only clients with a template or a 2026 invoice) and their buildings as objects. Apartment buildings get type "Bytový dom"; a container stand merges into the building it belongs to. Firm settings (contact, texts, mail templates, logo, signature) come from one firm the owner already configured (`--copy-settings-from`) and fill only empty fields. Rules: create-only and idempotent (a second run creates nothing); a record the owner deleted is never brought back; a filled field is never overwritten (exception: a postal code equal to the client's, corrected from the owner's map; a property manager's address never sets one); the owner must be an active member of every firm it touches; one invalid record rolls the whole run back. Recurring invoices (2026-11-05): one template per legacy monthly template and per confirmed manual group, on its object, billing the previous month, with the legacy items and prices; drafts for the months since that template's last legacy invoice (max 3 months back); each firm's 2026 invoice numbering continues from the legacy last number. Recurring drafts are never issued or mailed. Invoices (2026-11-09): the 2026 invoices of the 5 firms come in as history with their legacy numbers — open ones stay open (issued, or overdue when past due), legacy-paid ones get one payment on the legacy payment date; nothing is mailed. 2026-11-11, changed 2026-11-12: an imported invoice linked to an object with billing identity takes the whole buyer from the object's billing data when it is created. Later runs never change the buyer of an imported invoice (the re-sync is removed; owner may veto). Unlinked invoices keep the buyer from the legacy app. Not imported: invoices before 2026, expenses, contacts, users other than the owner, other legacy firms. Verified 2026-11-05 by tests and a local dry-run (counts only); the production run is not done.
- **Add another company** — Platform admin only (`users.is_platform_admin`; other users get 403 on POST /tenants and do not see the entry in the TenantSwitcher; `app:create-owner` still bootstraps firms from the CLI) web UI "Pridať novú firmu" modal (max-w-2xl, organized in 4 sections: Základné údaje / Adresa / Kontakt / Bankové údaje): name + ico (required); dic, vat_number, is_vat_payer, address_line, city, postal_code, country (optional, country defaults to SK); contact_email, contact_phone, iban, swift_bic (optional; IBAN/SWIFT regex patterns defined in TenantSupplierProfileData::IBAN_PATTERN / SWIFT_BIC_PATTERN, reused by InvoiceSettingsData); colour picker (8 DaisyUI presets, optional), copy_settings toggle (when enabled, copies invoice defaults invoice_template, recurring_default_state, default_constant_symbol, default_payment_type, default_currency, default_rounding_mode from active tenant into new tenant, plus invoice_number_format + vat_rate; explicit colour wins over source colour) → RegistrationService::addTenant passes full supplier profile via AddTenantData::toSupplierProfile() → new Tenant with populated supplier fields + TenantInterface (colour or null) + actor gets Admin role + session-bound active_tenant_id switched → TenantController::store redirects to dashboard with `tenant_created` flash if supplier profile complete (hasCompleteSupplierProfile()), else redirects to Settings→Invoicing with `tenant_created_complete_supplier` flash (D1: onboard owner to complete profile before any invoice can be issued; drafts allowed on incomplete profile). No leader invitation created (invitations only via Employees/Users modules, new employees created via UserService::create → RegistrationService::createInvitation).
- **Accept invitation** — Primary onboarding path post-bootstrap. Invitee: GET /invitations/{token} (guest-accessible, regex constraint, 404 if unknown) → InvitationAcceptPageData (4 states: expired/wrong_user/existing_user/new_user). Form states (existing/new): POST /invitations/{token} (throttle 5/min, Precognition) with AcceptInvitationData {password, name optional}. ## Authorization model (single axis)

Access = `user/permission axis` only. No plan/feature gating.

- **User/permission axis** — per-tenant Spatie RBAC. Roles bundle permissions; owner customizes per tenant. Example: a Sekretárka with no "edit clients" permission simply cannot. Enforced: BE Policy + `#[Authorize]` + FE `Can` component.
- **Render by capability, not by role.** UI conditionals never check `.roles()` or `.hasRole()`. Always use `Can` component or `useAuthorization().allows(permission)` check. Roles are custom per tenant; capabilities are the contract.

## Domain rules (Phase 2 — Multi-tenancy foundation + Phase 4 invoicing)

1. **Row-level isolation.** Every domain model MUST have `tenant_id` UUID FK + `BelongsToTenant` trait + `TenantScope` global scope (exceptions: User, Tenant, TenantMembership, TenantInterface, Role, Permission, Activity/Media/TemporaryUpload custom scopes). Phase 11 exceptions: global tasks (`tenant_id` NULL, creator-only via `TaskScope`), notifications with no company (nullable `tenant_id`), device tokens and mobile sessions (per person, no company), and task attachments (`media.tenant_id` NULL for personal tasks only, enforced by a DB CHECK; a firm task's files carry the firm's id). Phase 3+ models follow same pattern.
2. **Supplier profile completeness before issue.** An invoice cannot be issued until the company has a complete supplier profile: mandatory name, address_line, city, postal_code, ico (always); plus dic and vat_number when is_vat_payer=true. Drafts are allowed on incomplete profile; only the issue action is gated. New tenant created via "Add company" modal is immediately redirected to Settings→Invoicing to prompt completion (decision D1). Recurring auto-issue (auto_issue=true) generates invoices as Draft + skips issue if supplier incomplete (D2b), advancing the schedule anyway to avoid retry loops. User-facing banner (SupplierIncompleteAlert) appears when supplier incomplete, linking to settings drawer for quick completion.
2. **Team scope discipline.** Spatie Permission teams=true, team_foreign_key=tenant_id. Every role/permission check calls `setPermissionsTeamId(current_tenant_id)` first (middleware, service, test helpers, jobs, console commands). TenantContextMiddleware binds current_tenant_id container, PermissionRegistrar::setPermissionsTeamId(tenant_id).
3. **No cascades (D8).** FKs use `restrictOnDelete()` (prevents accidental cascades) except `invited_by_user_id → nullOnDelete` (inviter may be removed, invitation stays valid). Tenant/User deletion logic: soft-delete Tenant (cascades never fire), deactivate User (is_active=false, never hard-delete globally).
4. **Active membership = authenticated.** Login guards: `is_active=true` AND `hasActiveMembership()`. RequireActiveTenant middleware on all authenticated routes (web logout + redirect / API 403 on zero memberships). Mid-session membership deactivation → next request logs out.
5. **Invitation token (D10).** 64-char random, unique index, 7d expiry, single-use (`accepted_at` nulls out status). Throttle 5/min on POST accept. Plaintext (not hashed; deferred hardening, low-risk internal tool).
6. **No PermissionEnum duplication.** PermissionEnum is global catalogue (68 cases); roles bundle them per-tenant. FE auto-derives can keys from enum (sharedKey = Str::camel, no hand list). useAuthorization().allows(enum) reads page.props.can dynamically (ComputedRef).
7. **Signature snapshot at issue, live for drafts (Phase 10).** Invoice's supplier signature image is frozen at the moment of issue: `invoices.supplier_signature_media_id` captures the tenant's current `signature_media_id`. Draft invoices resolve the tenant's current signature live (FE preview shows "what will be printed"). Issued invoices retain the snapshot forever — if the owner later replaces the signature, reprints of historical invoices render the original image, not the new one. This is audit-compliance by design: the printed document matches the copy the customer received. No signature → no image block in the PDF. Motivation: supplier identity is already frozen on invoices (name, address, IČO, etc.) at issue; signature is part of that identity on a legal document. Storage: Tenant is a HasMedia owner with 'signature' collection (NOT singleFile) on private DOCUMENTS_DISK, so superseded uploads are retained.
8. **Issuer name snapshot from actor, never from request (Phase 10).** Invoice's issuer footer line ("Vystavil: {person}") is stamped from the actor's TenantMembership.display_name (first_name + last_name, fallback to User.name). Recurring auto-issued invoices have "Vystavil: Automaticky" (frozen translation at generation time in app locale). Drafts have no issuer name. Credit notes issued via cancel() also receive issuer + signature snapshots at cancel time. This prevents spoofing: request-supplied issuer names could let any user stamp a colleague's name on an invoice; actor comes from `$request->user()`, guaranteeing identity.
9. **Platform admin owns global content and firm creation (2026-10-31).** `users.is_platform_admin` is a single boolean on the user (not a tenant role, not fillable, never shown to the UI beyond `canCreateTenant`). It gates global document templates and `POST /tenants`. It deviates from the pure RBAC axis on purpose: the owner runs all firms, a tenant permission cannot gate cross-firm data, and an owner email is user-editable. Granted via `app:grant-platform-admin {email}` or by `app:create-owner` when none exists.
10. **A document keeps the text it was created with (2026-10-31).** Template edits (global or firm) never change existing contracts or sent quotes; contracts are frozen on signing (blocks expanded, PDF snapshot stored once); sent quotes freeze at send. A value missing at creation stays as a visible token until the user fills it; signing/sending is blocked while any remain.
11. **Sensitive employee data is fail-closed and minimal (2026-10-31).** Rodné číslo is encrypted at rest, masked on detail, full only on the edit form (audited), absent from logs, lists and queues; employee-subject contract text needs the same permission. Employee files are Admin-only, private, streamed through the app with audit, and permanently deleted on delete. Sample-only template preview ensures real identifiers never pass through the template editor.
12. **Document language is fixed (2026-10-31).** Contract/quote text, token values and document PDF labels render in the configured document locale (default Slovak) regardless of UI, CLI or queue language; invoice PDFs are unaffected.
13. **Buyer rule and billing visibility (2026-11-01).** The buyer of an invoice is the house when the object has billing details (`billing_name` filled), else the client, else the typed standalone customer; the three never mix. The e-invoice endpoint follows the buyer: a Peppol ID on the house (or, for a Slovak buyer, a 10-digit DIČ) routes to the house, and a house with neither is not e-invoice ready (normal invoice, PDF and send still work). Billing data is visible only with `ViewAllObjects` (same gate as contacts), so cleaners and schedule pickers never receive it. The house buyer is whole (2026-11-12): billing name, IČO, DIČ, VAT ID, Peppol ID, billing street, city, postal code and the object's country; the object's own address and the client's data never mix in. Invoices imported from the legacy app keep the buyer written when they were imported (the 2026-11-11 re-sync is removed; see Import legacy data).

14. **Quote billing periods, totals and branding (2026-11-03).** Each quote item is one-off, monthly, quarterly or yearly; the cleaning cadence is a separate field. Totals print per period group, never as one mixed total, and a group appears only when it has items. A quote converts to an invoice from its one-off items only; each recurring group converts only to a recurring invoice template that the accountant reviews and saves. "V cene je zahrnuté" is free text, one bullet per line, prefilled on new quotes from the firm default. The signing place (Settings → Fakturácia, Cenové ponuky) prints on quote PDFs. The system logo (Kegos Clean) prints on quote and invoice PDFs; a firm cannot upload its own logo (removed 2026-11-05). Invoice and recurring-invoice item descriptions are limited to 255 characters.

15. **No default recipient e-mail (2026-11-05).** Only a typed invoice `customer_email` is ever sent to. Client, object billing e-mail, object contacts and recurring template values are suggestions or explicit save targets, never fallbacks. Auto-send (recurring `auto_send`, job) requires a non-empty `customer_email`; a missing one is logged `skipped_no_email` and nothing is sent. The object billing e-mail prefills an empty invoice e-mail field only (editable; never sent automatically; 2026-11-12). Suggestions show only for actors with the matching view permission (`viewBilling` for the object billing e-mail, `viewContacts` for object contacts, `view` on the client for client contacts).
16. **Audit-log revert is an allowlist, not a generic undo (2026-11-03).** Only the plain fields listed per model in `ActivityRevertService` revert; status, number, stamps, money, assignment and identity never do. One user action = one `batch_uuid` (written only by ClientService, ObjectService and the revert itself). A batch reverts whole or not at all; a subject changed since the logged value is a conflict and is never overwritten.

17. **Missing item unit prints `mes.` (2026-11-06).** Invoice and recurring-invoice items with no unit get `mes.` (owner decision): the legacy importer writes it on every imported row, and the one-off data migration `2026_11_14_000100` fills existing empty units on every invoice status, issued ones included. New items keep the unit the form sends. Quote items are untouched.

18. **Bank payments are recorded once, in EUR, on payable invoices only (2026-11-10).** An incoming credit is matched to an issued or overdue invoice by its variable symbol, one payment to one invoice. A bank entry (account IBAN plus the bank's entry reference) is recorded at most once per firm while the payment is live; a deleted payment's entry can be recorded again by hand. An amount above the open balance records only the open amount; the excess is written in the payment note and reported, never recorded as a second payment. Credit notes and cancelled invoices never receive a bank payment. A row that would duplicate a payment of the same amount within 7 days is never recorded without the owner's choice.
19. **Payroll documents go into expenses, not a payroll module (2026-11-10).** No payroll tables and no server-side payslip parsing. An employee-linked expense is confirmed and names one person and one payroll month. A second payslip for the same person and month is a duplicate the user decides (keep both or replace); the check applies to category wages only. Undocumented cash names an employee and has no receipt; a receipt is never attached to it.
20. **A person with expenses stays in the firm's books (2026-11-10).** Removing a user from a firm is refused with 422 while any expense, soft-deleted ones included, references that membership. Deactivating the employee is unaffected: it keeps the membership.
21. **Token uploads add no new power (2026-11-10).** `/api/token/*` uses the caller's personal `mcp` token and the same permissions and company checks as the MCP tools; it is off unless the server enables it. Import and receipt writes are refused while the user is under the MCP prompt-injection restriction. An import records only the rows the server itself marks to import (matched or partial), minus the rows the caller excludes; the response carries no payer name and no bank note.
22. **A recorded contract file is identified by its content (2026-11-11).** Inside a firm a file contract is identified by the SHA-256 of its main file: the same file again is refused on the web (422 naming the existing contract) and returned unchanged on the token path. A soft-deleted contract does not block. Replacing the main file follows the same rule and is logged. A file contract is never generated text: recording it never dispatches ContractSigned, so no work breakdown, scheduled jobs or signed PDF snapshot. The signing date is never invented: "signed" with no date stays "date unknown", and an unsigned file stays unsigned.

23. **A sent quote goes back to draft when edited (2026-11-11).** Saving a Sent quote makes it a Draft again with the sent date cleared; the printed text and the PDF the customer holds do not change until it is sent again. Only a Draft quote can be deleted. Sending freezes the text it prints; the editor keeps the token text for the next send.
24. **Assistant files stay in their message (2026-11-11).** A file sent to the assistant is read only in that message and saved only onto records the assistant creates in it. It is not kept in the chat, not resent in later messages, and never reaches the AI task run. Undocumented cash expenses never get a file.

25. **Every itemized quote prints from a quote template (2026-11-12).** The text is the template the form picks, else the firm's default quote template (firm row before the global one, then by name), else the built-in KEGOS body. A save never deletes that text: an update that sends no text, over MCP too, keeps it. A quote saved before this rule prints the default until its first save; sending freezes the printed text. A quote uploaded as a file (kind document) has no text. Print rule for the buyer: a clientless quote prints the buyer typed on it; a quote linked to a client prints the client; a quote for an object with billing details prints only that object's billing data, with no client and no "V zastúpení" line. The buyer e-mail never prints, on a quote or on an invoice (2026-11-12). The invoice buyer follows rule 13.

26. **Search ignores accents and case; list filters are remembered (2026-11-12).** Text search and text filters match without accents and case in every list ("Rajecká" is found by "raje", "rajecka" and "RAJECKÁ"). Numbers, dates, statuses and ids stay exact. A list keeps its filters, sort and page for the browser session, per company, and the memory is cleared on logout. A link that carries its own query uses that query.

27. **Assistant conversations are private to their author (2026-11-13).** Each person has one assistant history across all companies, shared by web and mobile. Only the author can list, open, rename or delete it; another person's conversation is "not found", and no admin reads it. Delete needs no `use assistant` (the author's privacy control); view and rename need it. The history is stored encrypted and kept until the author deletes it (no retention purge); delete is permanent. Prepared actions stay on Pending actions. Attached files are not kept: only their names.

Columns: model morph (uuid), **tenant_id uuid NOT NULL** except for Task owners, which may be NULL for personal tasks (DB CHECK `media_tenant_required_unless_task`; the hook copies the owner's tenant). Created hook throws if unbound for other owners. Disk, size. Relations: inTenant scope.
- `TemporaryUpload` — staging for moveToModel. UUIDv7 PK. Columns: session_id, user_id FK (nullOnDelete), **tenant_id FK (restrictOnDelete)**, collection, timestamps. TenantScope applied. Relations: user (BelongsTo).
- `Role` — Spatie custom subclass. UUIDv7 PK. Columns: name, guard_name, **tenant_id uuid** (per-tenant roles). Methods: inTenant(tenant_id) scope, isSystem() (= ADMIN_ROLE). Unique (name, guard_name, tenant_id).

**Phase 3+ operational (reserved, not yet ported):**
- `Client` — typ: `Corporate` (firemný — IČO required; DIČ and IČ DPH optional on the client form, owner decision 2026-11-01) or `Private` (private person, IČO optional). The e-invoice card on the invoice detail (`InvoiceEfaCard`) warns when the customer has no valid DIČ or Peppol ID. The client's Peppol ID is the e-invoice endpoint only when the client is the buyer (no billing details on the object). When the object has billing details, the house is the buyer and the house's Peppol ID decides routing (2026-11-01). The buyer needs a Peppol ID, or for a Slovak buyer a 10-digit DIČ (endpoint 0245:DIČ); IČO is never an endpoint. Without one the invoice is not e-invoice ready (no XML, no submit); issue, PDF and ordinary send are unaffected. Has multiple contacts with primary flag. Soft-delete. Partial unique index on (tenant_id, ico) per tenant for active clients.
- `Object` — physical cleaning location (kancelária/byt/dom/spoločné priestory). The **central entity**: client → object → (quote → contract → invoices). Holds access info (codes, keys), special instructions.
- `Quote` (cenová ponuka) — items with name/description/frequency/unit/quantity/price. Status: Draft → Odoslaná → Schválená → Zamietnutá → Expirovaná. Auto-generates work breakdown.
- `DocumentTemplate` (replaces ContractTemplate) — reusable HTML text with `{{key}}` tokens; type (service_agreement/employment/nda/gdpr/other/quote), optional employment type, header/footer flags, active flag. `tenant_id` NULL = global (platform admin); firm override = row with `parent_id` + base snapshot (states base/customized/base_changed); firm-own rows. Soft-delete, audit logged.
- `Document` — polymorphic stored text or file (`documentable` = Contract, Quote or TenantMembership): type, title, encrypted body, header/footer flags, media `file`/`pdf` on the private documents disk. Contract/quote documents soft-delete with their owner; employee files hard-delete.
- `Contract` — **polymorphic** (`contractable_type` + `contractable_id`) targets CleaningObject (service agreement), Client (service agreement without object) or TenantMembership (employee contract). `document_template_id` FK (nullable; blank contract starts from a skeleton). Category + term_type (fixed/indefinite; fixed requires end_date). The text lives in its Document (resolved copy made at save, editable only in Draft, blocks frozen on sign, signed PDF snapshot stored). Status: Draft → Active (on sign) → Expired / Terminated (auto/manual). `valid_from`, `signed_at`, `terminated_at` tracking. Lifecycle guards: `isEditable()/canBeSigned()/canBeTerminated()`. Soft-delete, audit logged.
- `EmploymentContract` — child of Contract (HasOne). Type: DPP / DPČ / TPP / Živnosť. Fields: position, salary, hours, probation_end_date. Restrict FK to parent (parent is soft-deleted only); no soft-delete or audit log of its own.
- `WorkBreakdown` (rozpis prác) — generated from ServiceAgreement contract (one per contract). Decomposes quote line items into named tasks with recurrence frequency (one-time/weekly/seasonal). Has_one Contract. Drives scheduled-job generation on rolling schedule (daily cron). Soft-delete, audit logged.
- `WorkBreakdownTask` — child tasks of WorkBreakdown (one per quote item). Name, description, frequency, position. Cascade delete, no activity logging.
- `ScheduledJob` (Zákazka) — materialized cleaning job instance. Type: Regular / OneOff / Special. Status: Unassigned / Planned / InProgress / Completed / Unapproved / Cancelled. Single nullable `assigned_membership_id` (TenantMembership FK, tenant+active scoped). Soft-delete, audit logged. Has optional `work_breakdown_id` + `work_breakdown_task_id` FKs (when generated from recurrence), optional `contract_id` (backlink), optional `invoice_id` (reserved for Phase 2 time-tracking linkage).
- `Absence` (neprítomnosť) — cleaner-reported time off. Triggers notification flow listing affected jobs.
- `Invoice` — Mesačná / Jednorazová / Špeciálna. Status: Draft → Vystavená → Uhradená / Po splatnosti / Stornovaná. Pay-by-Square QR per Slovak standard.
- (Document templates: see `DocumentTemplate` above; DOCX export and BOZP training templates are not built.)
- `Notification` settings + log — DB / E-mail / Push channels. Configurable per role × type.

**Phase 11 entities:**
- `Task` (úloha) — firm task (`tenant_id` set) or global task (`tenant_id` NULL, owned by `created_by_user_id`). Status (5 values, see the board use-case); priority; due, reminder and reminded times; optional assignee (TenantMembership) and optional subject; source manual/voice/assistant/mcp. Soft-delete. Attachments: Media collection `attachments` owned by the task (hard delete per file; uploader kept in the file's custom properties).
- `Expense` (výdavok) — per company; status draft/confirmed; category (12); source manual/receipt/bank_statement/mcp; date, amount, currency, supplier; receipt file (private documents disk); import key (hash of camt053, IBAN and entry reference) unique per company for bank imports. Soft-delete.
- `PendingAction` (čakajúca akcia) — one prepared irreversible action: action, subject (type + id), payload and its hash, subject fingerprint, preview, channel (mcp/assistant), status pending/executed/cancelled/expired, expiry (10 min), confirmed channel (chat/app).
- `DeviceToken` (zariadenie) — a push token of one person's device (android/ios, app version, last seen); follows the person across companies. Removed with its mobile session (logout, revoke, expiry, password change or reset) or, when the person has no active company left, with all their devices.
- `MobileSession` (relácia mobilnej aplikácie) — one row per phone login: refresh token stored as a hash, the current access token, idle expiry after one year. Per person, no company. Revocations are recorded in the audit log as `mobile_session_revoked`.

## Compliance / non-functional

- **GDPR** — EU storage, right to erasure, consent.
- **Slovak VAT** — IČ DPH on tenant flips global VAT visibility. Default rate 23% (configurable for legislation changes).
- **Multi-tenant isolation** — strict row-level. Tested via global scope on every domain query.
- **Languages** — SK / EN / UA across all platforms (UA reflects Ukrainian cleaning workforce).
- **Mobile (Phase 2)** — offline-first; sync on reconnect.
- **Dashboard** — async widgets; one widget failure ≠ whole dashboard failure.
