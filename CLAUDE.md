# CleanMaster

Product name everywhere is `Kegos Clean` (the logo artwork still reads KEGOS); class names (`CleanMasterServer`) and the local `cleanmaster` MCP handle are unchanged.

Internal tool for the owner's cleaning companies (SK/CZ). Rebuilt on the canonical inogile `vue-skeleton`
(rebuild merged into `main`); business modules are ported phase by phase per
`.claude/plans/port-from-cleaning-software.md` (read ONLY when a parent passes it as `plan_path`).
Phase 11 (mobile admin API, tasks, expenses, AI assistant, MCP, push) is merged into `main`.
Task attachments (photos, PDF, Word, Excel on tasks; web and mobile) are merged into `main`, verified on web and in the browser build, not yet on a physical iPhone.
Task comments and AI task runs ("Nech to spraví AI", 2026-11-01) are on `main`: no real model run, no real `queue-ai` worker run, no browser run of run states.

## Conventions (key)
- UUIDv7 PK via `App\Concerns\HasUuids`
- Spatie Data DTOs (no FormRequest, no `$request->validate()`)
- Inertia + Spatie Data toArray response (no JsonResource)
- `final readonly class` services with `declare(strict_types=1)`
- `DB::transaction` in service, NOT in controller
- Spatie Permission via `App\Enums\PermissionEnum`, `#[Authorize]` per controller method, Policy per business model
- Spatie Activitylog on business models
- `env()` outside `config/` forbidden
- `php artisan typescript:transform` after every change in `app/Data/` or `app/Enums/`
- Reuse skeleton components: `AppLayout`, `DataTable`, `ConfirmDeleteModal`, `Pagination`, `PermissionManager`, `Forms/*` — never reinvent
- New entities via `/scaffold-module` (canonical Resource Recipe)
- Task attachments are `Task` HasMedia (collection `attachments`), not `Document`: Document is tenant-bound (NOT NULL `tenant_id`) and personal tasks have no firm; deviates from the Document-store advice in technical.md.
- Task comments (`TaskComment`) are a rule-6 exception: `tenant_id` is nullable, set only from the task, NULL on personal tasks, fail-closed `TaskCommentScope`. AI task runs (`TaskRun`) keep BelongsToTenant (`tenant_id` = the company the run acts in).

## Mobile admin app and AI (Phase 11)

- **Mobile rollout:** KEGOS design (Quasar `sym_r_` icons, Geist, bottom sheets) is done on mobile `main`; native builds not run.
- **Mobile app repo:** `git@github.com:VladimirGostik/cleaning-software-app.git` (separate checkout, expected at `../cleaning-software-app`). Types: `pnpm api-types:export` (script `scripts/export-api-types.mjs`) copies `resources/js/types/generated.d.ts` into it (default target `src/types/api.generated.d.ts`).
- **API surface:** `routes/api.php`. `/api` group order: `auth:sanctum` → `locale.api` → `user.active` → `ability:mobile` → `tenant.context` → `tenant.required` (login, refresh and revoke sit outside the ability group; logout is `auth:sanctum` + `locale.api` only). Mobile tokens carry ability `mobile` and are issued only to users with `access mobile app` in some company.
- **Mobile sessions (2026-11-01):** each mobile login creates a `MobileSession` row (rule-6 exception: per person, no Policy, no LogsActivity). Access token = Sanctum `mobile` PAT, 60 min (`config/mobile_auth.php`). Refresh token `<session uuid>.<secret>`, sliding 365 days idle, rotated on every refresh with a 60 s reuse grace; a reuse outside the grace kills that one session. `POST /api/auth/refresh` (401 = session dead) and `POST /api/auth/revoke` (204) sit under `throttle:mobile-token` (30/min per IP). `POST /api/auth/logout` stays for MCP bearer tokens and also revokes the session behind a mobile token. Login throttle `mobile-login`: 10/min per IP plus 5/min per e-mail + IP. `PUT /api/profile/password` keeps the calling phone and logs out the others; web `PUT /profile/password` and `POST /reset-password` log out every phone. `cleanup:mobile-sessions` runs daily at 12:00. Migration `2026_11_08_000100` deletes old `["mobile"]` tokens and all device rows, so everyone logs in once after deploy.
- **MCP:** `routes/ai.php`. `/mcp` group order: `auth:sanctum` → `locale.api` → `user.active` → `ability:mcp` → `throttle:mcp` (120/min per token). Tokens are personal (`mcp` ability, 180 days, max 10 per user, created in Profile).
- **Tenant context before route binding:** `TenantContextMiddleware` runs before `SubstituteBindings` (`bootstrap/app.php`), so scoped bindings resolve under the caller's company (security fix `6f08aa9`, not on `main`).
- **Tool layer:** 30 MCP tools (`CleanMasterServer::TOOLS`). The assistant gets 27: `confirm_action`, `delete_global_task` and `update_document_template` are excluded. Two-step confirmation: prepared actions expire after 10 minutes (24 hours for AI task run rows), carry a payload hash and a subject fingerprint, and a changed or deleted subject cancels them. MCP `confirm_action` (chat channel) may confirm only issue/send actions; the rest only in the app. The web chat card confirms in the app (click + CSRF-protected POST), not through the chat channel.
- **Web chat bubble (2026-11-01):** every page, for users with `use assistant` in the active company (Admin, Vedúca by default). Same endpoint and gate `chatIn` as mobile (`POST /assistant/messages` web, `/api/assistant/messages` mobile). No AI key → notice + disabled composer. Real assistant reply not verified locally (no API key used).
- **Assistant:** 20 s turn budget, 18 s per provider step, `MaxSteps(6)`, tool output capped at 20 000 chars, partial success returns HTTP 200. The first tool call past the budget tells the model to answer, a later one ends the turn (`AssistantTimeBudgetExceeded`), so a turn stays under Laravel Cloud's 60 s request limit.
- **Sync AI calls (deviation):** AI calls run inside the HTTP request, not in a queue (no `ShouldQueue` in `app/Ai` and `app/Services/Ai`), except the AI task run below. Accepted for the assistant's interactive latency; keep the timeouts above.
- **AI task run ("Nech to spraví AI", 2026-11-01):** `App\Jobs\RunTaskWithAi` on queue `ai` (`AI_TASK_RUN_QUEUE`, default `ai`), `Tries(1)`, `Timeout(85)`, `FailOnTimeout`, dispatched after commit. Budgets: turn 45 s, step 25 s, job 85 s, under the 90 s managed-queue limit (Laravel Cloud behaviour unverified). Queue `retry_after` stays 90. A run that runs out of time ends `could_not_finish` and the person continues with "Pokračovať". Stale runs end on read or start (`TaskRunService::expireIfStale`) and in the daily `cleanup:task-runs`; stale = queued over 15 min or running over 120 s. Routes on web and `/api`: `/tasks/{task}/thread`, `/comments`, `/ai-runs`, `/ai-run-status`; web polls the status every 3 s, mobile every 5 s, each backing off up to 60 s on failure. Permission `run tasks with ai` (Admin, Vedúca). A starter with live pending actions on the task cannot start a run (`can_start_run` false, 422 `status`). Prepared actions carry `task_run_id` and channel `task_run` (app-only, 24 h). Worker: compose service `queue-ai` and supervisor program `queue-worker-ai`, both `--tries=1 --timeout=85`. `AI_TASK_RUN_QUEUE` must be a real environment variable wherever supervisor runs, not only in Laravel's `.env`. On Laravel Cloud it is `default`, the single managed queue.
- **Push design:** FCM token on both platforms via `@capacitor-firebase/messaging` (mobile repo; TODO verify there). `FirebasePushSender` skips quietly when credentials are not configured (`push.skipped` log).
- **Prompt-injection guard (`app/Services/Ai/Guard/`):** deterministic detector (weighted rules, threshold 3, checks folded/homoglyph/squeezed variants, hidden Unicode, base64), no AI key needed; `php artisan ai:guard-verify` runs the attack and normal-text corpus. Assistant: tool output wrapped in a per-turn nonce block; a flagged user message, history, tool output or tool argument refuses all writes for that turn (`IsReadOnly` tools only; no attribute = write); caps `ai.guard.max_writes_per_turn` 10 and `max_prepares_per_turn` 5; reply filter withholds a nonce leak, strips markdown images, redacts secrets, strips links when restricted; reply field `security_notice`. MCP: flagged output is labelled `_security_notice`, a flagged argument refuses that call, and for `ai.guard.mcp_restriction_minutes` (15, renewed by each flagged read) every non-read-only tool is refused for that user (in-app confirmation still works). Values are scored one by one, the audit keeps the masked matched text only. `confirm_action` over MCP is allowed for issue/send actions (`ai.confirm_channels`), so a planted text the detector misses could reach it unless the client asks the user; remove `chat` there to close that. Expenses, bank CSV rows and task parsing drop flagged text. Audit: activity log `ai`, description `guard.prompt_injection`. Limits: heuristics catch known shapes only, receipts/images are screened only through the model's output, not verified against a live model.
- **Not built yet:** Claude web connectors and the Gmail flow need OAuth (Passport) and deployment; the `mcp` Bearer token works for local clients only.
- **External prerequisites (not in the repo):**
  - Anthropic API key (`ANTHROPIC_API_KEY`, backend only).
  - Firebase service account (`FIREBASE_CREDENTIALS`): project `kegos-clean`, local file `storage/app/private/firebase-credentials.json` (git-ignored); on Laravel Cloud the whole JSON sits in the variable, because the filesystem is ephemeral.

- **Task attachments (2026-11-01):** `/api/tasks/{task}/attachments` GET/POST and `/{attachment}` GET/DELETE (ability `mobile`). Direct multipart, one file per POST, no `/uploads` staging. 10 MB per file, 20 per task (`config/tasks.php`). ## Review rules

Synced with `laravel-13-conventions/references/review-checks.md` §"Distilled house rules" (master copy). See root `REVIEW.md` for the canonical list.

**Laravel 13 distilled house rules:**

1. Validation via Spatie Data attribute DTOs — no FormRequest, no `$request->validate()`, no JsonResource.
2. UUIDv7 PKs (`HasUuids`) — never `$table->id()` / `bigIncrements`.
3. Controllers thin — no business logic, no `DB::transaction` (service owns both). Every action authorizes through the model's Policy (L13 `#[Authorize]`, L10-12 `$this->authorize()`) in every auth profile; `role:` route groups are an extra outer layer, not a replacement.
4. `Inertia::render` props: Data DTO / `::collect(...)` / scalar only — never bare array / Model / paginator without `->through(...)`.
5. Every user-facing message via `__('<ns>.<key>')` from lang files (validation = auto-lookup, override only per-field via `messages()`); never literal strings. Logs stay English.
6. Response DTOs minimal — no speculative fields without a named consumer.
7. Backed enums for fixed value sets — no magic status/permission strings.
8. `env()` only in `config/`; URLs via named route + `route()`.
9. Eager-load accessed relations (`with` / `withCount`); no `Model::all()` in request paths.
10. Events/jobs dispatched inside a transaction: `ShouldDispatchAfterCommit` / `->afterCommit()`.
11. No comments that restate code — no prose docblocks, no `// Arrange` markers, no step narration; PHPDoc only for types PHP can't express (array shapes, generics). 1-line WHY only.

**Per-project enforcement:**

- **Auth profile:** rbac-full — Policies gate every action. Controllers use `#[Authorize($ability, $modelOrParam)]` attribute. Single authorization axis: RBAC permission only, except the documented `users.is_platform_admin` flag (global document templates, POST /tenants). Never use `role()` checks; always use `Can` component + `useAuthorization().allows(permission)`.
- **Multi-tenancy:** row-level via `tenant_id` FK. Every domain model MUST have `tenant_id` UUID FK + `BelongsToTenant` trait + `TenantScope` global scope (exceptions: global `Task` rows via `TaskScope`, `TaskComment` with nullable `tenant_id` (NULL on personal tasks only) and the fail-closed `TaskCommentScope`, `media.tenant_id` NULL for Task owners only (DB CHECK `media_tenant_required_unless_task`), nullable `notifications.tenant_id`, per-person `DeviceToken` and `MobileSession`). **CRITICAL:** `setPermissionsTeamId($tenantId)` must be called before any role/permission lookup outside HTTP requests (jobs, console, seeders, tests).
- **TypeScript code generation:** `#[TypeScript]` attribute on all DTOs + Enums. `php artisan typescript:transform` generates `resources/js/types/generated.d.ts`. FE imports from there.
- **Atomic transactions:** Multi-step operations (create owner, issue invoice, generate recurring invoice) wrapped in `DB::transaction` in Service (NEVER Controller). Events/jobs inside transaction must implement `ShouldDispatchAfterCommit`.
- **Spatie Data DTO boundary:** Controllers accept DTO params with `#[Validation]` attributes. No inline `$request->validate()`. No FormRequest. No JsonResource.
- **i18n via locale keys:** Every user-facing string via `__('<ns>.<key>')` from `lang/{sk,en,uk}/*.php`. Logs stay English.
- **AI tool layer:** tools (`app/Mcp/Tools/*`) hold no business logic; they authorise through `Gate::forUser` inside `ToolContext` and delegate to services. `confirm_action` is MCP-only (never in the assistant toolbox, `AssistantToolbox::EXCLUDED`); `delete_global_task` is excluded there too. Irreversible actions go through `prepare_action` + confirmation, never a direct tool call. The AI task run toolset (`AssistantToolbox::forTaskRun`) also excludes complete, update, assign and company-wide tools; `ReportTaskOutcomeTool` is run-only and never in `CleanMasterServer::TOOLS`.
