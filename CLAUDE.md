# CleanMaster

Internal tool for the owner's cleaning companies (SK/CZ). Rebuilt on the canonical inogile `vue-skeleton`
(rebuild merged into `main`); business modules are ported phase by phase per
`.claude/plans/port-from-cleaning-software.md` (read ONLY when a parent passes it as `plan_path`).
Phase 11 (mobile admin API, tasks, expenses, AI assistant, MCP, push) is merged into `main`.
Task attachments (photos, PDF, Word, Excel on tasks; web and mobile) are on `feat/task-attachments`.

## Stack
- Backend: Laravel 13, PHP 8.5 (Docker: `docker compose exec app php artisan ...`)
- Frontend: Inertia v3 + Vue 3 + TypeScript, Tailwind 4 + DaisyUI 5
- DB: PostgreSQL 16 (compose service `postgres`), Redis 7
- Mail: Mailpit (compose service `:8026`), SMTP in dev/test
- Queue: Database driver, background `queue` service (prod: supervisor) for InvoiceIssued + StoreSignedContractPdf (ContractSigned listener) + GenerateRecurringInvoiceJob + GenerateScheduledJobsJob + 6 queued notifications (InvoiceOverdue, ContractExpired, ContractExpiring, QuoteSent, QuoteExpiring, QuoteExpired) + TaskAssigned / TaskDue notifications (Phase 11)
- AI + MCP (Phase 11): laravel/ai ^0.7.2 (Anthropic, `AI_MODEL`, `ANTHROPIC_API_KEY` backend only; AI calls run synchronously in the request, see "Mobile admin app and AI"), laravel/mcp ^0.7 (`/mcp` + local `cleanmaster` server), kreait/laravel-firebase ^7.2 (FCM push, `FIREBASE_CREDENTIALS`)
- PDF/QR: spatie/laravel-pdf (chrome driver), chrome-php/chrome (pure-PHP DevTools), Alpine apk Chromium (arm64 native), qpdf binary (bulk invoice PDF merge), pay-by-square + bacon QR code
- Calendar: @fullcalendar/vue3 v6.1.21 (FullCalendar month/week view for schedule jobs)
- Documents: symfony/html-sanitizer 8 (document HTML allowlist), league/flysystem-aws-s3-v3 (documents disk `s3`, not verified against a real bucket), Tiptap 3.23 (document editor), vitest + happy-dom (`pnpm test`), ttf-liberation in the Docker images (PDF fonts)
- Main packages: Spatie Data 4, Permission 7 (teams mode), Activitylog 5, MediaLibrary 11, QueryBuilder 7 + `App\Utils\AllowedFilter`,
  TypeScript Transformer 3, Laravel Boost 2, Scribe; PHPUnit 12; Pint, PHPStan (Larastan), ESLint, Prettier, vue-tsc, Lefthook

## Conventions (key)
- UUIDv7 PK via `App\Concerns\HasUuids`
- Spatie Data DTOs (no FormRequest, no `$request->validate()`)
- Inertia + Spatie Data toArray response (no JsonResource)
- `final readonly class` services with `declare(strict_types=1)`
- `DB::transaction` in service, NOT in controller
- Spatie Permission via `App\Enums\PermissionEnum`, `#[Authorize]` per controller method, Policy per business model
- Spatie Activitylog on business models
- `env()` outside `config/` forbidden
- `php artisan typescript:transform` after every change in `app/Data/` or `app/Enums/`
- Reuse skeleton components: `AppLayout`, `DataTable`, `ConfirmDeleteModal`, `Pagination`, `PermissionManager`, `Forms/*` — never reinvent
- New entities via `/scaffold-module` (canonical Resource Recipe)
- Task attachments are `Task` HasMedia (collection `attachments`), not `Document`: Document is tenant-bound (NOT NULL `tenant_id`) and personal tasks have no firm; deviates from the Document-store advice in technical.md.

## Mobile admin app and AI (Phase 11)

- **Mobile app repo:** `git@github.com:VladimirGostik/cleaning-software-app.git` (separate checkout, expected at `../cleaning-software-app`). Types: `pnpm api-types:export` (script `scripts/export-api-types.mjs`) copies `resources/js/types/generated.d.ts` into it (default target `src/types/api.generated.d.ts`).
- **API surface:** `routes/api.php`. `/api` group order: `auth:sanctum` → `locale.api` → `user.active` → `ability:mobile` → `tenant.context` → `tenant.required` (login and logout sit outside the ability group). Mobile tokens carry ability `mobile` and are issued only to users with `access mobile app` in some company.
- **MCP:** `routes/ai.php`. `/mcp` group order: `auth:sanctum` → `locale.api` → `user.active` → `ability:mcp` → `throttle:mcp` (120/min per token). Tokens are personal (`mcp` ability, 180 days, max 10 per user, created in Profile).
- **Tenant context before route binding:** `TenantContextMiddleware` runs before `SubstituteBindings` (`bootstrap/app.php`), so scoped bindings resolve under the caller's company (security fix `6f08aa9`, not on `main`).
- **Tool layer:** 30 MCP tools (`CleanMasterServer::TOOLS`). The assistant gets 27: `confirm_action`, `delete_global_task` and `update_document_template` are excluded. Two-step confirmation: prepared actions expire after 10 minutes, carry a payload hash and a subject fingerprint, and a changed or deleted subject cancels them. Chat may confirm only issue/send actions; the rest only in the app.
- **Assistant:** 45 s turn budget (gates the start of each tool call), 30 s per provider step, `MaxSteps(6)`, tool output capped at 20 000 chars, partial success returns HTTP 200. Worst case with a model that keeps requesting tools is about 6 × 30 s, so the proxy and PHP timeout must be at least 90 s (nginx here: `fastcgi_read_timeout 300`).
- **Sync AI calls (deviation):** AI calls run inside the HTTP request, not in a queue (no `ShouldQueue` in `app/Ai` and `app/Services/Ai`). Accepted for the assistant's interactive latency; keep the timeouts above.
- **Push design:** FCM token on both platforms via `@capacitor-firebase/messaging` (mobile repo; TODO verify there). `FirebasePushSender` skips quietly when credentials are not configured (`push.skipped` log).
- **Prompt-injection guard (`app/Services/Ai/Guard/`):** deterministic detector (weighted rules, threshold 3, checks folded/homoglyph/squeezed variants, hidden Unicode, base64), no AI key needed; `php artisan ai:guard-verify` runs the attack and normal-text corpus. Assistant: tool output wrapped in a per-turn nonce block; a flagged user message, history, tool output or tool argument refuses all writes for that turn (`IsReadOnly` tools only; no attribute = write); caps `ai.guard.max_writes_per_turn` 10 and `max_prepares_per_turn` 5; reply filter withholds a nonce leak, strips markdown images, redacts secrets, strips links when restricted; reply field `security_notice`. MCP: flagged output is labelled `_security_notice`, a flagged argument refuses that call, and for `ai.guard.mcp_restriction_minutes` (15, renewed by each flagged read) every non-read-only tool is refused for that user (in-app confirmation still works). Values are scored one by one, the audit keeps the masked matched text only. `confirm_action` over MCP is allowed for issue/send actions (`ai.confirm_channels`), so a planted text the detector misses could reach it unless the client asks the user; remove `chat` there to close that. Expenses, bank CSV rows and task parsing drop flagged text. Audit: activity log `ai`, description `guard.prompt_injection`. Limits: heuristics catch known shapes only, receipts/images are screened only through the model's output, not verified against a live model.
- **Not built yet:** Claude web connectors and the Gmail flow need OAuth (Passport) and deployment; the `mcp` Bearer token works for local clients only.
- **External prerequisites (not in the repo):**
  - Anthropic API key (`ANTHROPIC_API_KEY`, backend only).
  - Firebase service account (`FIREBASE_CREDENTIALS`).
  - Apple Developer Program membership + APNs key (iOS push).
  - Domain and final `APP_ID` (open item, mobile repo).
- **Task attachments (2026-11-01):** `/api/tasks/{task}/attachments` GET/POST and `/{attachment}` GET/DELETE (ability `mobile`). Direct multipart, one file per POST, no `/uploads` staging. 10 MB per file, 20 per task (`config/tasks.php`). PHP `upload_max_filesize=12M`, `post_max_size=14M` from `docker/php/uploads.ini`; a request over 14 MB gets 413. Throttle `task-attachments` 60/min. AI and MCP see only `attachments_count`.
- **Mobile attachments:** the upload queue and the camera (`Services.Camera`, `Camera.pickImages`) live in the mobile repo `cleaning-software-app`, which now has vitest (35 tests).
- **Laravel Cloud risks:** Chromium (PDF), `qpdf` binary (bulk invoice PDF), S3 documents disk (not verified against a real bucket; task attachments use the same disk).
- **Open risk, production `Dockerfile` build (not fixed, not built):** `.dockerignore` excludes `docker/` (line 18), but `Dockerfile` copies `docker/php/php-fpm.conf` (line 84), `docker/nginx/default.conf` (line 110) and `docker/supervisor/supervisord.conf` (line 113) from the build context, so the build likely fails there. The new `!docker/php/uploads.ini` re-include covers only the upload-limits file. Read-verified only.
- **Configuration keys:** `.env.example` already lists `ANTHROPIC_API_KEY`, `AI_MODEL`, `FIREBASE_CREDENTIALS`, `DOCUMENTS_DISK`, `SCHEDULING_HORIZON_DAYS`. `config('ai.providers.anthropic.key')` resolves through laravel/ai's merged defaults (verified).

## Review rules

Synced with `laravel-13-conventions/references/review-checks.md` §"Distilled house rules" (master copy). See root `REVIEW.md` for the canonical list.

**Laravel 13 distilled house rules:**

1. Validation via Spatie Data attribute DTOs — no FormRequest, no `$request->validate()`, no JsonResource.
2. UUIDv7 PKs (`HasUuids`) — never `$table->id()` / `bigIncrements`.
3. Controllers thin — no business logic, no `DB::transaction` (service owns both). Every action authorizes through the model's Policy (L13 `#[Authorize]`, L10-12 `$this->authorize()`) in every auth profile; `role:` route groups are an extra outer layer, not a replacement.
4. `Inertia::render` props: Data DTO / `::collect(...)` / scalar only — never bare array / Model / paginator without `->through(...)`.
5. Every user-facing message via `__('<ns>.<key>')` from lang files (validation = auto-lookup, override only per-field via `messages()`); never literal strings. Logs stay English.
6. Response DTOs minimal — no speculative fields without a named consumer.
7. Backed enums for fixed value sets — no magic status/permission strings.
8. `env()` only in `config/`; URLs via named route + `route()`.
9. Eager-load accessed relations (`with` / `withCount`); no `Model::all()` in request paths.
10. Events/jobs dispatched inside a transaction: `ShouldDispatchAfterCommit` / `->afterCommit()`.
11. No comments that restate code — no prose docblocks, no `// Arrange` markers, no step narration; PHPDoc only for types PHP can't express (array shapes, generics). 1-line WHY only.

**Per-project enforcement:**

- **Auth profile:** rbac-full — Policies gate every action. Controllers use `#[Authorize($ability, $modelOrParam)]` attribute. Single authorization axis: RBAC permission only, except the documented `users.is_platform_admin` flag (global document templates, POST /tenants). Never use `role()` checks; always use `Can` component + `useAuthorization().allows(permission)`.
- **Multi-tenancy:** row-level via `tenant_id` FK. Every domain model MUST have `tenant_id` UUID FK + `BelongsToTenant` trait + `TenantScope` global scope (exceptions: global `Task` rows via `TaskScope`, `media.tenant_id` NULL for Task owners only (DB CHECK `media_tenant_required_unless_task`), nullable `notifications.tenant_id`, per-person `DeviceToken`). **CRITICAL:** `setPermissionsTeamId($tenantId)` must be called before any role/permission lookup outside HTTP requests (jobs, console, seeders, tests).
- **TypeScript code generation:** `#[TypeScript]` attribute on all DTOs + Enums. `php artisan typescript:transform` generates `resources/js/types/generated.d.ts`. FE imports from there.
- **Atomic transactions:** Multi-step operations (create owner, issue invoice, generate recurring invoice) wrapped in `DB::transaction` in Service (NEVER Controller). Events/jobs inside transaction must implement `ShouldDispatchAfterCommit`.
- **Spatie Data DTO boundary:** Controllers accept DTO params with `#[Validation]` attributes. No inline `$request->validate()`. No FormRequest. No JsonResource.
- **i18n via locale keys:** Every user-facing string via `__('<ns>.<key>')` from `lang/{sk,en,uk}/*.php`. Logs stay English.
- **AI tool layer:** tools (`app/Mcp/Tools/*`) hold no business logic; they authorise through `Gate::forUser` inside `ToolContext` and delegate to services. `confirm_action` is MCP-only (never in the assistant toolbox, `AssistantToolbox::EXCLUDED`); `delete_global_task` is excluded there too. Irreversible actions go through `prepare_action` + confirmation, never a direct tool call.
